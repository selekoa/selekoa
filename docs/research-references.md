# Research references and documentary exports

Links use URL fragments and work with the existing static deployment at any base path. No server routing is required.

| Target                       | Fragment                                                   |
| ---------------------------- | ---------------------------------------------------------- |
| Start page                   | empty fragment                                             |
| Record explorer              | `#/explore`                                                |
| Document history             | `#/documents/COLLECTION_ID`                                |
| Document page                | `#/document/DOCUMENT_ID`                                   |
| Person page                  | `#/person/PERSON_ID`                                       |
| Claim and Evidence Inspector | `#/claim/CLAIM_ID`                                         |
| Institutional dossier        | `#/dossier/INSTITUTION_ID`                                 |
| Question page                | `#/question/QUESTION_ID`                                   |
| Question section             | `#/question/QUESTION_ID?section=SECTION_ID`                |
| Question reading position    | `#/question/QUESTION_ID?section=SECTION_ID&claim=CLAIM_ID` |

Earlier `#/reading/…` addresses take the same parameters and still resolve; the application then shows the `#/question/…` form. Person and document addresses resolve only for an entity of that type.

Question, person, document, document-history and dossier URLs can add `inspect=CLAIM_ID` to restore an open Evidence Inspector alongside the selection. IDs are encoded as URL components. Reading claims must belong to the named section when both are supplied. The application updates its address using replacement history as the user selects records; it does not create a browser-history entry for each focus change. External hash navigation and browser history traversal restore the target. Display filters and theme are not part of these references.

Malformed or missing IDs show a visible notice and the overview. No substitute record is guessed. Superseded claims retain their original record and expose explicit predecessor/replacement controls. These links resolve in the installed dataset, not against an immutable historical release. Source references contain the source's own canonical and inspected-expression URLs.

Copy actions are available in the Evidence Inspector, dossier and guided reading. Clipboard failure reveals selectable text. Claim references identify the stored claim, qualification, temporal scope, editorial state and full dataset fingerprint. Publication references use stored authors, title, publisher, publication date, version, version date when recorded, URLs and recorded access date. Unknown publication dates remain unknown. They are plain bibliographic references, not a claim of compliance with a particular citation style.

The Anthropic reading offers UTF-8 Markdown (`.md`) and structured JSON (`.json`) downloads of the entire defined selection, including optional branches. Format version 1 keeps selection identity, version, ordering, rationale, warnings, prose and supporting claim IDs separate from complete claim records and source metadata. Evidence references retain locators, source/support roles, check dates, notes and actual verification/reviewer fields. Claim acceptance never implies that all evidence or reading prose was human-reviewed. Quotes and paraphrases are omitted from both formats; original documents are never bundled. Attribution, licence, reuse notes and upstream metadata travel with their sources. Endpoint entity metadata is included in JSON, with identity-source metadata as well as claim-linked sources.

Generation is independent of React and uses no clock, random values or external fetches. A full-dataset SHA-256 fingerprint and a selection fingerprint identify canonical JSON with sorted object keys, preserved array order and UTF-8 encoding. Whitespace and object-key ordering in the original files do not affect the fingerprint; array reordering does. Metadata update dates and selection versions are retained but are insufficient identifiers by themselves. Reproduction requires the same complete dataset, selection and export implementation; the packet is a subset and cannot reconstruct the full dataset. Fingerprints do not retrieve a Git revision or prove authenticity. Retain the matching repository snapshot separately for high-reliance use.

No metadata fingerprint, recorded access date, current source URL or archive link authenticates an earlier document expression. Exact editions, persistent publication identifiers and archived originals are only as complete as stored metadata. There is no DOI lookup, CSL/BibTeX/RIS export, citation-style engine, immutable release resolver or independently authenticated source archive. Academic reliance still requires manual inspection of the exact original sources and claims used.

Fingerprinting uses native Web Crypto and requires a secure browser context (HTTPS or localhost). Clipboard restrictions reveal a manual-copy field; fingerprint failures stop claim-reference generation or download with a visible error.

## Document histories and research starters

`src/domain/document-history.ts` projects exact framework editions (`documentVersion` entities) and the stored claims about them: publication, `supersedes_document`, `changes_from`, `applies_framework`, explicit credit, quoted provisions (`states_provision`) and recorded absences (`provision_not_found`). Replacement appears only where a claim records it. Each family also lines its provisions up by key across editions: each cell is a stored provision, a recorded absence or nothing recorded; nothing is inferred. Coverage gaps are derived, not asserted: a later edition with no replacement claim, or with no recorded change, is labelled as a gap in this dataset rather than as unchanged. The collection definition, limits and open questions live in `src/reading/frontier-safety-frameworks.ts`; each open question cites existing claim IDs. The selection is machine-proposed and not human-reviewed.

The page downloads a research starter (`selekoa-research-starter`, format version 1) as Markdown and JSON. Unlike the reading packet it carries passages: stored editorial paraphrases, and short quotes only where the source's recorded reuse note permits minimal excerpts; other quotes are omitted with a reason. It also carries complete claim records, locators, roles, verification states, per-edition coverage gaps, open questions, inferences with rationale, each edition’s provision, absence and provision-assessment claim IDs with the family’s provision alignment, a disagreement section that lists every contested or unresolved record with its evidence grouped by side (or states that none is recorded), scoped review status, source metadata with reuse terms, and dataset and collection fingerprints. Generation is deterministic and React-independent. Original documents are never bundled; academic reliance still requires inspecting the exact original editions.

## Person, document and question pages

`src/domain/person-profile.ts` projects one person's stored claims into a documented path (role, founding, launch and departure records in date order), an Undated group, works authored, explicit credits to the person, governance-topic records and any other relation. Snapshots are shown as dated points and intervals keep only stated boundaries; no transition, tenure or end date is computed. "What this record cannot tell you" is derived from those same records: snapshots, open intervals, undated records, sources published after the period they describe, sources with unknown publication dates, and institutions with no recorded end or departure. The person starter reuses the research-starter core and passage rules; its JSON carries a `person` block with the projection version, section claim IDs and computed limits instead of a collection definition.

`src/domain/document-record.ts` projects one document: issue and authorship claims, dates with their stated basis, exact source expressions, its version family through the same `familyHistory` projection as document histories, and each documentary relation (cites, cited by, explicitly credits, reports using a method from, method used by, applies, discusses, reports evaluation of) as its own labelled list. Relations are a table, so later relations such as explicit replies, and later version families such as working-paper and journal versions, add rows rather than page types.

Question pages generalise the guided reading. A `QuestionSelection` (`src/domain/research-path.ts`) has a question, one principal section, optional context branches, authored passages, optional record groups, an optional anchoring institution and optional authored open questions. "What is disputed" lists contested or unresolved selected records and contradicting evidence; "Open questions and limits" collects each branch's stated limit and every record warning. Both are computed, so they cannot drift from the stored claims. The Anthropic question is unchanged in content and keeps selection version 3; its export remains the format-version-1 reading packet.

A question starter (`QuestionStarterDefinition` in `src/domain/question-starter.ts`) answers a question with existing records only and adds no connecting prose. Its definition names the documents in scope and a set of sections, each made of record groups chosen by explicit claim IDs or by stated rules (predicate, subject, object, resolution). A record may appear in one group only. The chronology is computed from the selected issue, enactment and self-described link records; a statute's entry into force comes from its document metadata and cites the enactment record's history-note evidence. Open questions and questions set aside are reused verbatim from the commitments and document-history collections when they concern a selected record. "What Selekoa cannot answer here" is authored per question, with three computed lists: enacted laws recorded, frameworks with no recorded link to an in-scope text, and listed signatories with no recorded framework. Each gap also carries a candidate research task; `pnpm question:gaps` writes them to `review/essay-starter-gaps.md`, and a unit test fails while that file is stale. The tasks are not authorised work.

The first starter, `frameworks-to-obligations` (`src/reading/self-governance.ts`, `#/question/frameworks-to-obligations`), asks how frontier-AI developers' self-governance changed from voluntary frameworks to legal obligations in 2023–2026. Its starter export cites the original source first (title, publisher, date, location, archived copy) and the Selekoa claim and evidence IDs second; in JSON each `citations` entry has `original` before `selekoa`. Passages follow the research-starter reuse rules. A `section` parameter opens the page at one part.
